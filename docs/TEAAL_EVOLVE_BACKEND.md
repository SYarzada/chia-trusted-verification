# TeAAL-Evolve Kernels and Design Options

TeAAL-Evolve describes accelerator designs as tensor computations, schedules,
storage choices, and hardware bindings. This reference explains the eight kernel
examples and lists their design options in detail. For setup and runnable CHIA
commands, use the [TeAAL-Evolve quickstart](TEAAL_EVOLVE_QUICKSTART.md).

## How CHIA uses these inputs

1. TeAAL loads a kernel YAML file and the Trainium architecture YAML as one
   candidate design.
2. The [CHIA worker](../src/chia_trusted_verification/backends/teaal_evolve/worker.py)
   reads the kernel's selected mutation options, tries each against the
   configured starting design, and assigns an ID to each effective change.
3. A search method selects IDs from that catalog. The worker applies the
   chosen changes together to a copy of the starting design.
4. The configured TeAAL checker verifies the complete result. If it passes,
   TeAAL evaluates its bottleneck objective; CHIA records the result and
   returns feedback to the search method.

The tables below describe the **original example seeds** in
[`teaal_evolve/example/kernel/nki/`](../teaal_evolve/example/kernel/nki/).
The reported multi-run experiments use the separate
[`selected_seeds/`](../teaal_evolve/example/kernel/nki/selected_seeds/) files;
their starting values can differ. The active CHIA catalog comes from the
selected options in [`mutation_profiles.py`](../teaal_evolve/src/trans/certify/mutation_profiles.py)
after the worker filters out changes that cannot be applied or leave its
configured seed unchanged. A listed rich option is therefore a possible
design change, not necessarily an option offered in every CHIA run.

## Reading the kernel sections

- A **tensor** is an input, intermediate value, state, or output. A **rank**
  is one of its index dimensions; tiled ranks such as `M1` and `M0` divide a
  larger dimension. A **stage** computes or moves data.
- A **binding** places a tensor in memory (`HBM`, `SBUF`, or `PSUM`) or assigns
  one or more stages to an engine and instruction. Other storage components
  shown in the placement tables are fixed for the listed placement options.
- **Loop order** sets the nesting of stage iterations. **Spacetime** assigns
  ranks to parallel hardware (`space`) or repeated execution (`time`).
  **Format rank order** sets the rank order at a tensor's use. These choices
  do not change the kernel's mathematical expression.
- Tensor names are local to each example. `H` often means an HBM-facing
  copy, `S` a staged copy, `P` a partial result, and `T` a reordered copy.
  The rank and tensor tables in each section give the actual meaning.

The four detailed option lists are generated by the [rich knob rules](../teaal_evolve/src/trans/certify/knobs.py):

| Option type | Available choices |
| --- | --- |
| Tensor component | `SBUF`, `PSUM`, or `HBM`; one choice updates all bindings of the named logical tensor. |
| Loop order | Current order, reverse, rotation of the first rank to the end, and a shortened order without the last rank; duplicate values are omitted. |
| Spacetime | Current mapping; the last loop rank in space and the others in time; and a mapping built from the current space ranks plus all but the last loop rank in time. |
| Format rank order | Current order, reverse, and an order without the last rank. |
| Engine instruction | Each engine and instruction pair listed below, for each engine binding entry. |

Some generated choices deliberately omit or repeat ranks and can fail
verification. Other choices can conflict when combined, such as moving a
tensor to storage its consumer cannot read. CHIA verifies the complete
candidate before scoring it.

In a list such as `mapping.loop_order::ZS`: `[N,M]` → `[M,N]` → `[N]`, the
arrows separate **alternative values of one option**. They do not mean that
CHIA applies three changes in sequence. The first value is the original
seed's value. In spacetime entries, `space=[M];time=[N]` is the exact value
syntax accepted by TeAAL. A selected mutation written as a knob ID without
`=value` advances that knob to its next available value.

Each kernel's **Selected mutation options** lists the distinct option strings
from the search options in `mutation_profiles.py`. These are a smaller set
than the generated rich options above. For one kernel, the same option occurs
in two internal categories; it is shown once here. The worker filters the
list against the active seed as described above.

## Kernel: `unary`

This is the smallest end-to-end elementwise kernel in the suite. It loads a two-dimensional tensor from HBM, squares every element independently, and stores the squared tensor back to HBM; there is no reduction or recurrence between elements.

### Ranks

| Rank | Meaning in this kernel |
|---|---|
| `M` | First independent element dimension (size 512). It is not reduced; every `(m,n)` element is squared independently. |
| `N` | Second independent element/tile dimension (size 128). The seed maps this rank spatially/partitions storage by it. |

### Tensors

| Tensor | Meaning |
|---|---|
| `AH[M,N]` | Input array in the host/HBM-facing representation. |
| `AS[M,N]` | On-chip/staged copy of the input after `DMAEngine::Load`; this is the operand consumed by the square operation. |
| `ZS[M,N]` | Elementwise result `AS^2`. `Z` denotes the result family and `S` is its staged/local representation in the seed. |
| `ZH[M,N]` | HBM/output representation of the squared result after the store stage. |

### Stages and engines

| Stage | Expression | Current engine binding |
|---|---|---|
| `AS` | `AS[m, n] = AH[m, n]` | `DMAEngine::Load` |
| `ZS` | `ZS[m, n] = AS[m, n] ;; M unary[square]` | `ScalarEngine::Unary` |
| `ZH` | `ZH[m, n] = ZS[m, n]` | `DMAEngine::Store` |

### Tensor placement and use

| Tensor | Ranks | Current component | Used/bound at stages |
|---|---|---|---|
| `AH` | `[M,N]` | `HBM` | `AS` |
| `AS` | `[M,N]` | `SBUF` | `AS`, `ZS` |
| `ZS` | `[M,N]` | `SBUF` | `ZS`, `ZH` |
| `ZH` | `[M,N]` | `HBM` | `ZH` |

### Tensor-component mutation options

- `binding.tensor.component::AH`: current `HBM`; allowed `[SBUF, PSUM, HBM]`. The mutation updates all binding entries for `AH` together.
- `binding.tensor.component::AS`: current `SBUF`; allowed `[SBUF, PSUM, HBM]`. The mutation updates all binding entries for `AS` together.
- `binding.tensor.component::ZS`: current `SBUF`; allowed `[SBUF, PSUM, HBM]`. The mutation updates all binding entries for `ZS` together.
- `binding.tensor.component::ZH`: current `HBM`; allowed `[SBUF, PSUM, HBM]`. The mutation updates all binding entries for `ZH` together.

### Loop-order options

- `mapping.loop_order::AS`: `[N,M]` → `[M,N]` → `[N]`
- `mapping.loop_order::ZS`: `[N,M]` → `[M,N]` → `[N]`
- `mapping.loop_order::ZH`: `[N,M]` → `[M,N]` → `[N]`

### Spacetime options

- `mapping.spacetime::AS`: `space=[N];time=[M]` → `space=[M];time=[N]` → `space=[N];time=[N]`
- `mapping.spacetime::ZS`: `space=[N];time=[M]` → `space=[M];time=[N]` → `space=[N];time=[N]`
- `mapping.spacetime::ZH`: `space=[N];time=[M]` → `space=[M];time=[N]` → `space=[N];time=[N]`

### Format rank-order options

- `format.rank_order::AH::AS`: `[N,M]` → `[M,N]` → `[N]`
- `format.rank_order::AS::AS`: `[N,M]` → `[M,N]` → `[N]`

## Kernel: `unary_reduce_one_tile`

This kernel extends the unary square with a reduction. It first squares every element of a `K × M × N` input, then sums those squared values across `K` to produce an `M × N` reduction result; the seed stores both the unreduced squared tensor and the reduced result.

### Ranks

| Rank | Meaning in this kernel |
|---|---|
| `K` | Reduction dimension (size 512). `RS[m,n]` sums `ZS[k,m,n]` over `k`. |
| `M` | Small non-reduced outer dimension (size 2). |
| `N` | Non-reduced element/partition dimension (size 128); it is the main partition rank in the seed mapping. |

### Tensors

| Tensor | Meaning |
|---|---|
| `AH[K,M,N]` | Original HBM input tensor. |
| `AS[K,M,N]` | Loaded/staged input used by the square stage. |
| `ZS[K,M,N]` | Elementwise square of `AS`; it still retains `K` because reduction has not happened yet. |
| `RS[M,N]` | Reduction-sum result: `ZS` accumulated over `K`. The disappearance of `K` from the ranks is the key sign that `K` is reduced. |
| `ZH[K,M,N]` | Stored copy of the unreduced squared tensor `ZS`. |
| `RH[M,N]` | Stored copy of the reduced result `RS`. |

### Stages and engines

| Stage | Expression | Current engine binding |
|---|---|---|
| `AS` | `AS[k, m, n] = AH[k, m, n]` | `DMAEngine::Load` |
| `ZS` | `ZS[k, m, n] = AS[k, m, n] ;; M unary[square]` | `ScalarEngine::UnaryReduce` |
| `RS` | `RS[m, n] = ZS[k, m, n] ;; V binary[add]` | `ScalarEngine::UnaryReduce` |
| `ZH` | `ZH[k, m, n] = ZS[k, m, n]` | `DMAEngine::Store` |
| `RH` | `RH[m, n] = RS[m, n]` | `DMAEngine::Store` |

### Tensor placement and use

| Tensor | Ranks | Current component | Used/bound at stages |
|---|---|---|---|
| `AH` | `[K,M,N]` | `HBM` | `AS` |
| `AS` | `[K,M,N]` | `SBUF` | `AS`, `ZS` |
| `ZS` | `[K,M,N]` | `SBUF` | `ZS`, `RS`, `ZH` |
| `RS` | `[M,N]` | `SBUF` | `RS`, `RH` |
| `ZH` | `[K,M,N]` | `HBM` | `ZH` |
| `RH` | `[M,N]` | `HBM` | `RH` |

- `binding.tensor.component::AH`: current `HBM`; allowed `[SBUF, PSUM, HBM]`. The mutation updates all binding entries for `AH` together.
- `binding.tensor.component::ZS`: current `SBUF`; allowed `[SBUF, PSUM, HBM]`. The mutation updates all binding entries for `ZS` together.

### Loop-order options

## Kernel: `vector_scalar_overlap`

This compact pipeline combines tensor, scalar, and vector-style operations. It loads an input tensor, reorganizes/broadcasts it by introducing `Q`, applies an elementwise exponential, and then performs a running sum across `P` to produce the final `M × N × Q` output, making it useful for exercising dependencies and overlap across several engine types.

### Ranks

| Rank | Meaning in this kernel |
|---|---|
| `M`, `N` | Independent outer/tile dimensions. In the seed, different stages choose `M` or `N` as the main partition/spatial rank. |
| `Q` | Replication/broadcast dimension introduced by `AT`; the same `AS[m,n,p]` value is logically available for each `q`. |
| `P` | Accumulation dimension. `ZS` walks through `p` and adds `BS[...,p]`. |
| `PI` | Recurrence/prefix-state index corresponding to the running accumulation over `P`. `ZS[...,0]` is initialized and `ZS[...,p+1]` is updated from `ZS[...,p]`. |

### Tensors

| Tensor | Meaning |
|---|---|
| `AH[M,N,P]` | HBM input tensor. |
| `AS[M,N,P]` | Loaded scratch representation of the input. |
| `AT[M,N,Q,P]` | Transposed/reorganized/broadcasted version of `AS` with an added `Q` rank; produced by the TensorEngine transpose stage. |
| `BS[M,N,Q,P]` | Elementwise exponential of `AT`. |
| `ZS[M,N,Q,PI]` | Running prefix sum of `BS` along `P`; state 0 is initialized to zero and each update adds one `p` element. |
| `ZH[M,N,Q]` | Final sum after the recurrence reaches `P`; this is the HBM-facing output. |

### Stages and engines

| Stage | Expression | Current engine binding |
|---|---|---|
| `AS` | `AS[m, n, p] = AH[m, n, p]` | `DMAEngine::Load` |
| `AT` | `AT[m, n, q, p] = AS[m, n, p]` | `TensorEngine::Transpose32` |
| `BS` | `BS[m, n, q, p] = AT[m, n, q, p] ;; M unary[exp]` | `ScalarEngine::Unary` |
| `ZS_init` | `ZS[m, n, q, 0] = 0` | `VectorEngine::MemSet` |
| `ZS` | `ZS[m, n, q, p + 1] = ZS[m, n, q, p + 0] . BS[m, n, q, p] ;; M binary[add]` | `VectorEngine::TensorTensorSP` |
| `ZH` | `ZH[m, n, q] = ZS[m, n, q, P]` | `DMAEngine::Store` |

### Tensor placement and use

| Tensor | Ranks | Current component | Used/bound at stages |
|---|---|---|---|
| `AH` | `[M,N,P]` | `HBM` | `AS` |
| `AS` | `[M,N,P]` | `SBUF` | `AS`, `AT` |
| `AT` | `[M,N,Q,P]` | `PSUM` | `AT`, `BS` |
| `BS` | `[M,N,Q,P]` | `PSUM` | `BS`, `ZS` |
| `ZS` | `[M,N,Q,PI]` | `SBUF` | `ZS_init`, `ZS`, `ZH` |
| `ZH` | `[M,N,Q]` | `HBM` | `ZH` |

## Kernel: `attention`

This is a conventional numerically stable attention computation: it forms `QK` dot-product scores, subtracts the per-query maximum, exponentiates the shifted scores, forms the softmax denominator, and computes the normalized score-weighted sum of `V`. The many intermediate tensors and transposes expose the tiled data movement, reductions, and TensorEngine/VectorEngine/ScalarEngine stages needed to realize that attention pipeline on the target architecture.

### Ranks

| Rank | Meaning in this kernel |
|---|---|
| `E` | Query/key dot-product feature dimension (128). `QKP` multiplies `QS` and `KS` and reduces over `E`. |
| `F` | Value/output feature dimension (128). The final attention-weighted value is indexed by `F`. |
| `P3,P2,P1,P0` | Hierarchical/tiled **query-position** ranks. Together they represent the query/output position space at the implementation level. |
| `P2U` | A staged/unflattened representation of the `P2` query-position rank used by several scratch tensors. It is an implementation representation rank, not a new semantic attention dimension. |
| `M2,M1,M0` | Hierarchical/tiled **key/value-position** ranks. These are the positions reduced over by softmax and by the attention-times-value computation. |

### Tensors

| Tensor | Meaning |
|---|---|
| `QH[E,P3,P2,P1,P0]` | Query tensor in its HBM/host representation. |
| `QS[E,P3,P2U,P1,P0]` | Loaded/staged query tensor used by the QK dot product. |
| `KH[E,M2,M1,M0]` | Key tensor in HBM/host representation. |
| `KS[E,M2,M1,M0]` | Loaded/staged key tensor. |
| `VH[F,M2,M1,M0]` | Value tensor in HBM/host representation. |
| `VS[F,M2,M1,M0]` | Loaded/staged value tensor. |
| `VTP[M0,M2,M1,F]` | Value transpose/reordering intermediate; it reorganizes `VS` for the later score-times-value stage. |
| `VTS[M0,M2,M1,F]` | Staged form of the transposed/reordered value tensor. |
| `QKP[P3,P2,P1,P0,M2,M1,M0]` | Partial/computed `Q*K` attention score tensor after multiplying over `E` and reducing the dot product. |
| `QKS[P3,P2U,P1,P0,M2,M1,M0]` | Staged score tensor derived from `QKP`; this is the score representation consumed by the softmax-max path. |
| `GMPR[P3,P2U,P1,P0,M2]` | Partial maximum reduction of `QKS`; `M1` and `M0` have been reduced away. |
| `GMT[P3,P2U,P1,P0]` | Maximum temporary after the remaining `M2` reduction. This is the per-query maximum score. |
| `GM[P3,P2U,P1,P0]` | Negated maximum (`-GMT`), used so adding `GM` to each score performs `score - max`. |
| `QKSGM[...]` | Stabilized/shifted attention scores `QKS - max`. It retains all key-position ranks. |
| `SN[...]` | Softmax numerator values `exp(QKS - max)`. |
| `SNTP[...]` | Transpose/reorder intermediate for the softmax numerator before multiplication by `V`. |
| `SNTS[...]` | Staged/transposed softmax-numerator tensor consumed by the value-product stage. |
| `SD[P3,P2U,P1,P0]` | Softmax denominator: sum of the exponentials over all key/value positions. |
| `SDR[P3,P2U,P1,P0]` | Reciprocal of the softmax denominator, `1/SD`. |
| `SNVP[P3,P2,P1,P0,F]` | Numerator-times-value reduction: accumulated `SN * V` over the key/value-position ranks. |
| `AV[P3,P2U,P1,P0,F]` | Normalized attention output, `SNVP * SDR`. |
| `AVZ[P3,P2,P1,P0,F]` | Final staged/output representation of the attention value. |

### Stages and engines

| Stage | Expression | Current engine binding |
|---|---|---|
| `KS` | `KS[e, m2, m1, m0] = KH[e, m2, m1, m0]` | `DMAEngine::Load` |
| `VS` | `VS[f, m2, m1, m0] = VH[f, m2, m1, m0]` | `DMAEngine::Load` |
| `VTP` | `VTP[m0, m2, m1, f] = VS[f, m2, m1, m0]` | `TensorEngine::Transpose16` |
| `VTS` | `VTS[m0, m2, m1, f] = VTP[m0, m2, m1, f]` | `ScalarEngine::TensorCopy` |
| `QS` | `QS[e, p3, p2 + 0, p1, p0] = QH[e, p3, p2, p1, p0]` | `DMAEngine::Load` |
| `QKP` | `QKP[p3, p2, p1, p0, m2, m1, m0] = QS[e, p3, p2 + 0, p1, p0] . KS[e, m2, m1, m0] ;; M binary[multiply] V binary[add]` | `TensorEngine::MatMul16` |
| `QKS` | `QKS[p3, p2 + 0, p1, p0, m2, m1, m0] = QKP[p3, p2, p1, p0, m2, m1, m0] . 0 ;; M binary[add]` | `VectorEngine::TensorConstReduce` |
| `GMPR` | `GMPR[p3, p2 + 0, p1, p0, m2] = QKS[p3, p2 + 0, p1, p0, m2, m1, m0] ;; V binary[maximum]` | `VectorEngine::TensorConstReduce` |
| `GMT` | `GMT[p3, p2 + 0, p1, p0] = GMPR[p3, p2 + 0, p1, p0, m2] ;; V binary[maximum]` | `VectorEngine::TensorReduceNegate` |
| `GM` | `GM[p3, p2 + 0, p1, p0] = -1 . GMT[p3, p2 + 0, p1, p0] ;; M binary[multiply]` | `VectorEngine::TensorReduceNegate` |
| `QKSGM` | `QKSGM[p3, p2, p1, p0, m2, m1, m0] = QKS[p3, p2 + 0, p1, p0, m2, m1, m0] . GM[p3, p2 + 0, p1, p0] ;; M binary[add]` | `ScalarEngine::BiasedUnaryReduce` |
| `SN` | `SN[p3, p2 + 0, p1, p0, m2, m1, m0] = QKSGM[p3, p2, p1, p0, m2, m1, m0] ;; M unary[exp]` | `ScalarEngine::BiasedUnaryReduce` |
| `SD` | `SD[p3, p2 + 0, p1, p0] = SN[p3, p2 + 0, p1, p0, m2, m1, m0] ;; V binary[add]` | `ScalarEngine::BiasedUnaryReduce` |
| `SNTP` | `SNTP[p3, p2, m0, m2, m1, p1, p0] = SN[p3, p2 + 0, p1, p0, m2, m1, m0]` | `TensorEngine::Transpose16` |
| `SNTS` | `SNTS[p3, p2 + 0, m0, m2, m1, p1, p0] = SNTP[p3, p2, m0, m2, m1, p1, p0]` | `ScalarEngine::TensorCopy` |
| `SDR` | `SDR[p3, p2 + 0, p1, p0] =  1 . SD[p3, p2 + 0, p1, p0] ;; M binary[divide]` | `VectorEngine::Reciprocal` |
| `SNVP` | `SNVP[p3, p2, p1, p0, f] = SNTS[p3, p2 + 0, m0, m2, m1, p1, p0] . VTS[m0, m2, m1, f] ;; M binary[multiply] V binary[add]` | `TensorEngine::MatMul16` |
| `AV` | `AV[p3, p2 + 0, p1, p0, f] = SNVP[p3, p2, p1, p0, f] . SDR[p3, p2 + 0, p1, p0] ;; M binary[multiply]` | `VectorEngine::TensorScalar` |
| `AVZ` | `AVZ[p3, p2, p1, p0, f] = AV[p3, p2 + 0, p1, p0, f]` | `DMAEngine::Store` |

## Kernel: `one_pass_attention`

This kernel computes attention using an online/one-pass softmax formulation so key/value blocks can be processed incrementally instead of requiring the full attention-score matrix to be retained at once. It maintains a running maximum (`RM`), running denominator (`RD`), and running weighted-value numerator (`RNV`), rescales the accumulated state whenever the maximum changes, and finally divides the accumulated numerator by the denominator; this seed also contains an explicit pipelining schedule.

### Ranks

| Rank | Meaning in this kernel |
|---|---|
| `E` | Query/key dot-product feature dimension. |
| `F` | Value/output feature dimension. |
| `P4,P3,P2,P1,P0` | Hierarchical/tiled query-position ranks. `P4` is an additional outer query/block rank compared with the conventional attention kernel. |
| `M3,M2,M1,M0` | Hierarchical/tiled key/value-position ranks processed block by block by the online softmax recurrence. |
| `M3I,M2I` | Recurrence/state indices corresponding to boundaries between processed `M3/M2` blocks. The running max/denominator/numerator tensors need an initial state plus updated states, hence the `I` form. |

### Tensors

| Tensor | Meaning |
|---|---|
| `QH[...]`, `KH[...]`, `VH[...]` | HBM/host query, key, and value inputs. |
| `QS[...]`, `KS[...]`, `VS[...]` | Loaded/staged query, key, and value tensors used by compute stages. |
| `BQKP[...]` | Block-local QK dot-product result (partial/computed block attention scores). |
| `BQKS[...]` | Staged block QK scores used by the online-softmax path. |
| `LMT[...]` | Local maximum temporary obtained by reducing a score block over `M1,M0`. |
| `LM[...]` | Negated local maximum (`-LMT`). The recurrence stores the negative-max form, allowing a `minimum` update to represent the new global negative maximum. |
| `RM[...]` | Running maximum state in that negated representation. It is initialized, updated for each score block, and copied across outer blocks. |
| `RMS[...]` | Snapshot of the previous running-max state before the current update. |
| `BQKSRM[...]` | Current block scores shifted by the updated running maximum, i.e. the stabilized scores used before exponentiation. |
| `SLN[...]` | Stabilized local softmax numerator, `exp(shifted block score)`. |
| `SLD[...]` | Sum of the current block's stabilized numerators; the local contribution to the denominator. |
| `SLNTP[...]` | Reorder/transpose intermediate for `SLN`. |
| `SLNTS[...]` | Staged reordered local numerator tensor. |
| `SLNTVP[...]` | Local numerator-times-value partial reduction. |
| `SLNTVS[...]` | Staged local numerator-times-value result used in the running numerator update. |
| `RMSB[...]` | Difference between the new and previous running-max states. |
| `PRM[...]` | Exponential correction factor derived from `RMSB`; it rescales previously accumulated state when the running maximum changes. |
| `SPD[...]` | Previous running denominator multiplied by the correction factor. |
| `RD[...]` | Running softmax denominator across processed key/value blocks. |
| `SPNV[...]` | Previous running numerator/value accumulation multiplied by the correction factor. |
| `RNV[...]` | Running numerator-times-value accumulation across processed blocks. |
| `RDR[...]` | Reciprocal of the final running denominator. |
| `AVS[...]` | Final normalized attention value `RNV * RDR`. |
| `AVH[...]` | HBM/output-facing attention result. |

This is the pipelined one-pass attention variant; its YAML adds a `pipelining:` schedule over `M2P3P2`.

## Kernel: `one_pass_attention_no_pipelining`

This kernel performs the same one-pass/online attention computation and uses the same running-max, running-denominator, and running-weighted-value recurrence as `one_pass_attention`. The key difference is the implementation seed: it omits the explicit pipelining schedule and uses a different `P3/P2` tiling shape, allowing the scheduling/pipelining choice to be studied without changing the underlying attention mathematics.

### Ranks

This kernel uses the same logical tensor/rank vocabulary as `one_pass_attention`; the difference is in implementation scheduling/options rather than the mathematics.

| Rank | Meaning in this kernel |
|---|---|
| `E` | Query/key dot-product feature dimension. |
| `F` | Value/output feature dimension. |
| `P4,P3,P2,P1,P0` | Hierarchical/tiled query-position ranks. |
| `M3,M2,M1,M0` | Hierarchical/tiled key/value-position ranks processed by the online-softmax recurrence. |
| `M3I,M2I` | State/boundary indices for the running recurrence. |

### Tensors

The tensor meanings are mathematically the same as in `one_pass_attention`; they are repeated here so this kernel section is self-contained. The difference between the two seeds is scheduling/pipelining configuration, not these tensor definitions.

| Tensor | Meaning |
|---|---|
| `QH[...]`, `KH[...]`, `VH[...]` | HBM/host query, key, and value inputs. |
| `QS[...]`, `KS[...]`, `VS[...]` | Loaded/staged query, key, and value tensors used by compute stages. |
| `BQKP[...]` | Block-local QK dot-product result. |
| `BQKS[...]` | Staged block QK scores used by the online-softmax path. |
| `LMT[...]` | Local maximum temporary after reducing a score block over `M1,M0`. |
| `LM[...]` | Negated local maximum. |
| `RM[...]` | Running maximum state, represented in the negated-max form used by this recurrence. |
| `RMS[...]` | Snapshot of the previous running maximum before the current block update. |
| `BQKSRM[...]` | Block scores shifted relative to the updated running maximum. |
| `SLN[...]` | Stabilized local softmax numerator (`exp` of shifted scores). |
| `SLD[...]` | Sum of the local stabilized numerators; current block's denominator contribution. |
| `SLNTP[...]` | Reorder/transpose intermediate for `SLN`. |
| `SLNTS[...]` | Staged reordered local numerator. |
| `SLNTVP[...]` | Local numerator-times-value partial reduction. |
| `SLNTVS[...]` | Staged local numerator-times-value result. |
| `RMSB[...]` | Difference between new and previous running-max states. |
| `PRM[...]` | Exponential correction/rescaling factor generated from `RMSB`. |
| `SPD[...]` | Previous denominator state rescaled by `PRM`. |
| `RD[...]` | Running softmax denominator. |
| `SPNV[...]` | Previous numerator/value state rescaled by `PRM`. |
| `RNV[...]` | Running numerator-times-value accumulation. |
| `RDR[...]` | Reciprocal of the final running denominator. |
| `AVS[...]` | Final normalized attention value. |
| `AVH[...]` | HBM/output-facing attention result. |

The `_init`, `_update`, and `_copy` stages initialize these running states, advance them after each processed key/value block, and carry the final state into the next outer block.

## Kernel: `matmul`

This is a tiled matrix multiplication: the TensorEngine forms partial products while reducing over the inner `K0` dimension, and a vector recurrence accumulates those partial products across `K1`. After all reduction tiles have been accumulated, the result is stored as the final tiled `M × N` output.

### Ranks

| Rank | Meaning in this kernel |
|---|---|
| `M1,M0` | Outer/inner tiles of the matrix-output row dimension `M`. |
| `N1,N0` | Outer/inner tiles of the matrix-output column dimension `N`. |
| `K1,K0` | Outer/inner tiles of the reduction/inner-product dimension `K`. Multiplication reduces across `K0`, then the recurrence accumulates across `K1`. |
| `K1I` | Running-state index for the accumulation across `K1`. `ZS[0,...]` is the initial zero state and `ZS[k1+1,...]` is the updated state. |
| `K00`, `K01`, `M00`, `M01`, `N00`, `N01` (mapping-only sub-ranks) | Hardware-level partitions created from `K0`, `M0`, and `N0`; they are tiling/mapping artifacts rather than new mathematical matrix dimensions. |

### Tensors

| Tensor | Meaning |
|---|---|
| `A[K1,K0,M1,M0]` | Original matrix-A input in a tiled representation. |
| `AH[K1,K0,M1,M0]` | HBM-facing/renamed form of `A`. |
| `AS[K1,K0,M1,M0,N1]` | Loaded/staged A tile, logically made available across the `N1` output-column tile rank. |

## Kernel: `mamba`

This kernel implements the selective state-space recurrence used by a Mamba-style computation. For each time step it forms the transition factor `exp(delta × A)` and the input contribution `delta × u × B`, updates the recurrent hidden state, projects that state through `C`, and reduces the projected contributions across the state dimension `N`; recurrence proceeds through `T0` and is carried across outer `T1` blocks.

### Ranks

| Rank | Meaning in this kernel |
|---|---|
| `B` | Batch dimension. |
| `D1,D0` | Outer/inner tiles of the model/channel dimension `D`. |
| `N` | State-space/state dimension. The final output contribution is accumulated across `N`. |
| `NI` | Prefix/running-state index for accumulation across the state dimension `N`; `ZS[...,0,...]` is initialized and `ZS[...,n+1,...]` accumulates the next state contribution. |
| `T1,T0` | Outer/inner tiles of the sequence/time dimension `T`. The recurrent state advances through `T0` and is carried between `T1` blocks. |
| `T1I` | Boundary/state index used to carry the hidden state between outer `T1` time blocks. |
| `D10,D11` and concatenations such as `D11ND10` (mapping-only) | Hardware-level sub-ranks/flattened ranks created while partitioning the `D` and `N` dimensions. |

### Tensors

| Tensor | Meaning |
|---|---|
| `A[D1,D0,N]` | State-transition parameter/input `A` for the selective state-space recurrence. |
| `BF[B,N,T1,T0]` | External B-like/input-dependent state-space coefficient tensor (named `BF` in the seed). |
| `C[B,N,T1,T0]` | C coefficient used to project hidden state contributions to the output. |
| `DF[B,D1,D0,T1,T0]` | External delta/step-size-like input tensor (the seed's `D`-family input, named `DF`). |
| `U[B,D1,D0,T1,T0]` | Main input activation `u`. |
| `AH`, `BH`, `CH`, `DH`, `UH` | HBM-facing/staged copies of the five corresponding external inputs above. |
| `ZERO[D0,T0]` | Explicit all-zero tile used to initialize output accumulation. |
| `I[B,D1,D0,N,T1I]` | Hidden/recurrent boundary state carried between `T1` blocks. It is initialized to zero and updated from the final `H` value of each block. |
| `AS[B,D1,D0,N]` | Staged/broadcasted form of `A`, made batch-aware for the recurrence. |
| `BS[B,N,T1,T0]` | Staged B coefficient. |
| `CS[B,N,T1,T0]` | Staged C coefficient. |
| `DS`, `DP`, `DT` | Successive staged/copied forms of the delta/step-size tensor. The multiple names expose pipeline/storage points even when the mathematical value is unchanged. |
| `US[B,D1,D0,T1,T0]` | Staged input activation. |
| `DU[...]` | Elementwise `delta * u`. |
| `DA[B,D1,D0,N,T1,T0]` | Elementwise `delta * A`. |
| `EDA[...]` | `exp(delta * A)`, the multiplicative state-transition factor. |
| `DUB[...]` | Input contribution `delta * u * B`. |
| `DUBT[...]` | Staged/reordered copy of `DUB` used by the recurrence. |
| `SI[...]` | Intermediate state term: previous/boundary hidden state multiplied by `EDA`. |
| `H[...]` | Updated hidden state: `SI + DUBT`. It is recurrent along `T0`. |
| `HT[...]` | Staged copy of `H` for the output projection path. |
| `HC[...]` | Hidden-state contribution multiplied by `C`: `H * C`. |
| `ZS[B,D1,D0,NI,T1,T0]` | Running accumulation of `HC` over state rank `N`. |
| `ZH[B,D1,D0,T1,T0]` | Final output after the `N` accumulation completes. |
| `Z[B,D1,D0,T1,T0]` | Final output representation returned by the kernel. |
